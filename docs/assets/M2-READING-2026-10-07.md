`python tools/assets/lossless.py --verify` prints `0 mismatches`; the ledger records 0 proof failures and **applied 0**. Applied stays 0 because of the net-bytes test, not because of a threshold. Measured by C6 at `c3b8e3e` (see `docs/assets/LOSSLESS.md`):

| Measure | Value |
| --- | ---: |
| candidate pngs / excluded / measured | 350 / 43 / 307 |
| files that clear 10 percent and 64 KiB | 17 |
| their saving at HEAD | 6574653 (6.27 MiB) |
| their history growth (sum of newBytes) | 18630921 (17.77 MiB) |
| files that clear the net-bytes test (saved > newBytes) | 0 |
| smaller by any amount, no threshold | 230 files, 10792695 bytes (10.29 MiB) |

Git keeps the old blob, so rewriting a tracked png adds newBytes to history and removes only oldBytes minus newBytes from the checkout. Total repo bytes would rise by 12056268 to save 6574653 at HEAD. Retroactive recompression is declined on that arithmetic. The saving left to take is at ingest: `python tools/assets/lossless.py --ingest` recompresses a png that has not been committed, with no threshold, because it costs no history.
